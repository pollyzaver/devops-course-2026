# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто указатель (40-байтовый файл со ссылкой на коммит),
создание ветки не копирует файлы проекта. В SVN ветвление реализовано как
полное копирование директории репозитория, поэтому создание и поддержка
веток требует больше места и времени, особенно на больших проектах.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: у разработчика нет локальной копии
истории репозитория, только текущая рабочая копия файлов. Любой коммит
сразу отправляется на центральный сервер, поэтому без подключения к нему
закоммитить изменения нельзя (можно только продолжать редактировать файлы
локально, а сам коммит выполнить позже).

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Legacy-проекты (особенно в госсекторе и банках), которые исторически
  используют SVN и не мигрировали на Git.
- Проекты с большими бинарными файлами, где централизованная модель и
  блокировка файлов (file locking) удобнее, чем распределённая история Git.
- Команды, которым нужен простой линейный контроль доступа на уровне папок
  и не требуется офлайн-работа с полной историей.
