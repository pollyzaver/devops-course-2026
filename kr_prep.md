# Подготовка к контрольной работе №4

## 1. Когда я выберу rebase, а когда merge? Почему?
Rebase — для локальной feature-ветки перед открытием PR, чтобы причесать
историю. Merge — для слияния уже опубликованных/общих веток, где над ними
могут работать другие люди.

## 2. Что произойдёт, если я сделаю rebase публичной ветки, с которой работают коллеги?
История ветки перепишется (изменятся хеши коммитов), и у коллег, которые
уже склонировали старую версию, при следующем pull возникнут конфликты и
дублирующиеся коммиты — их локальная история разойдётся с удалённой.

## 3. Зачем нужен multi-remote и в каких реальных сценариях он применяется?
Multi-remote позволяет одной командой push отправлять код сразу в
несколько репозиториев — например, основной на GitHub и зеркало (backup)
на GitLab, или репозиторий команды и публичный fork для open source.
